# Архитектура системы

## Текущая реализация

Telegram-бот на Python получает обновления через long polling. Бизнес-логика и интеграция с Google Calendar находятся преимущественно в `classroom_bot/bot.py`; функции проверки времени вынесены в `bot_utils.py`. Заявки сохраняются в `pending_bookings.json`, администраторы — в `admin_users.csv`. Это серверные модули бота: проверка ролей здесь не является проверкой на клиентском устройстве.

В репозитории присутствуют `max_bot.py` и `max_notifier.py`. MAX-сценарий частично реализован: есть меню и метод записи заявки, но просмотр занятости обозначен как разрабатываемый, а обработчик продолжения бронирования отсутствует. Полный сценарий не подтверждён.

ID используемого календаря читается из переменной окружения GOOGLE_CALENDAR_ID. Собственного HTTP API, FastAPI-сервера, PostgreSQL и миграций в текущем проекте нет.
