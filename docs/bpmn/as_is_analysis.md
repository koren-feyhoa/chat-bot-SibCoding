# Анализ текущего процесса As-Is

Рассматривается действующая Telegram-версия и частичная реализация MAX. Схема показывает основной сценарий согласования; детали обработчиков кода могут отличаться.

## Шаги процесса

| Роль | Действие | Данные |
| --- | --- | --- |
| Клиент | Открывает Telegram-бот и вводит ФИО, дату, интервал и описание. | Данные заявки |
| Бот | Проверяет формат данных и занятость через Google Calendar. При ошибке предлагает исправить ввод. | Запрос календаря и результат проверки |
| Бот | Сохраняет свободный интервал как ожидающую заявку в JSON и отправляет уведомление администратору. | Заявка pending и уведомление |
| Администратор | Открывает заявку, принимает решение; при отказе указывает причину. | Одобрение или отказ |
| Бот и Google Calendar | При одобрении обеспечивают событие бронирования и отправляют клиенту результат. | Событие календаря и уведомление |

## Узкие места и потери времени

| Узкое место | Причина | Последствие |
| --- | --- | --- |
| Незавершённый канал MAX | Модули уже есть, но просмотр занятости содержит заглушку и полный диалог не подключён. | Клиенту приходится переходить в Telegram или обращаться к администратору. |
| Один календарь на конфигурацию | Используется GOOGLE_CALENDAR_ID из окружения; справочника помещений в БД нет. | Для подключения нового помещения требуется дополнительная настройка, единый выбор помещений отсутствует. |
| Файловое хранение заявок | Два процесса могут перезаписать один JSON без общей транзакции. | Возможны восстановление потерянных данных и повторное согласование заявки. |
| Обработка решения человеком | Новая заявка ожидает рассмотрения администратором. | Время ожидания зависит от занятости сотрудника; фактическая длительность не измерена. |
| Сопровождение списков и журналов | Администраторы хранятся в CSV, сведения о действиях — в логах. | Требуются доступ к файлам и ручная сверка при изменении прав и разборе спорных ситуаций. |

Фактические длительности шагов и очередь заявок не измерены. Потери времени описаны качественно; численные оценки не выдаются за результаты наблюдений.

[Схема As-Is](as_is.png). ID календаря берётся из переменной окружения; CSV читается при проверке прав, поэтому обязательный перезапуск после каждого изменения списка не утверждается.
